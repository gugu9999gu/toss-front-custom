# FrontRecord 1.9.9 · 시스템 내비게이션과 오버레이 종료

LineageOS에서 홈·최근 앱으로 실제 이동해도 음악 시각화가 화면을 계속 덮는 문제가 보고됐습니다. 1.9.8은 배경과 조작 화면을 두 개의 전체 화면 오버레이로 만들고, 시스템 내비게이션에 맞춰 종료하지 않았습니다. 기존 닫기는 애니메이션 완료 뒤 서비스를 멈췄으므로 애니메이션 취소에도 의존했습니다.

1.9.9는 홈·최근 앱·화면 꺼짐에서 두 창을 즉시 제거하고 서비스를 종료합니다. 해당 이동에는 웹 앱을 다시 띄우는 동작을 하지 않습니다. ×·알림의 닫기와 다른 설정 화면 이동도 같은 정리 경로를 사용합니다. 열린 설정·기록·예약 창, 카메라, 표시 갱신과 애니메이션을 함께 정리합니다. 중복 종료는 무시하며 늦게 도착한 닫기 요청만으로 화면을 다시 열지 않습니다. 표시 종료 자체는 미디어 일시정지 명령을 보내지 않습니다. 기록·즐겨찾기·예약·테마 저장 형식은 바꾸지 않았습니다.

조작 창이 뒤로가기를 받도록 만들고 Android 13 이상의 Back dispatcher도 등록합니다. 설정 창이 열려 있으면 먼저 닫고, 다음 뒤로가기로 재생 화면을 닫습니다. 홈·최근 앱의 시스템 닫기 알림은 수신만 하며 앱에서 제한된 시스템 방송을 보내지 않습니다. [Android 시스템 닫기 동작 변경](https://developer.android.com/about/versions/12/behavior-changes-all#close-system-dialogs), [Back dispatcher](https://developer.android.com/reference/android/window/OnBackInvokedDispatcher).

2026-10-12 Android 16/API 36 시뮬레이터에서 1.9.8의 오버레이 두 창이 홈 이동 후에도 남는 것을 재현했습니다. 같은 환경의 1.9.9에서 홈·최근 앱·뒤로가기 후 두 창과 서비스가 없는 것을 확인했습니다. 설정 창을 연 상태의 홈 이동, 설정 창부터 닫는 뒤로가기, × 종료, 화면 꺼짐·켜짐 후 자동 재등장 방지를 확인했습니다. 로컬 시험용 미디어 세션이 계속 PLAYING 상태이고 홈 뒤 소스 앱을 다시 앞으로 띄우지 않는 것도 확인했습니다. 시험 소스는 네트워크 요청이나 소리를 내지 않습니다.

예약·감도·기록 이동·제스처·추적·목록·모션의 Java 검사 201개와 웹 구간 이동 검사 10개를 통과했습니다. 같은 서명의 앱 업데이트를 사용하고 설치 APK SHA-256을 빌드 결과와 대조했습니다. 이 검증은 실제 YouTube 음성 재생이나 LineageOS 실물에서의 동작 확인을 대신하지 않습니다. 이번 요청에서는 실물 기기에 설치하지 않았습니다. [검증 결과](frontrecord-overlay-verification.json).

# 기기별 백업과 복구

첫 번째 기기에서 확인된 방식입니다. 다른 모델·GPT·저장장치에서는 이 값을 그대로 쓰지 않습니다.

## 연결

마이크로 USB는 PC 데이터 연결, C타입은 전원에 사용했습니다. EDL 진입은 마이크로 USB를 유지한 채 C타입 전원을 분리하고, 하단 커버 안의 EDL 버튼을 누른 상태로 C타입 전원을 다시 연결하는 방식입니다. 인식 후 버튼을 놓습니다. EDL에서 화면이 검게 유지될 수 있습니다.

Windows에 Qualcomm 9008 장치가 나타나는지 확인합니다. 장치가 없거나 설명자 오류가 나면 파티션 쓰기를 시작하지 않습니다. 정상 부팅에서는 토스 앱이 실행된 후 USB 연결이 해제될 수 있습니다.

## 읽기와 백업

1. 장치·칩셋과 Firehose 호환성을 확인합니다.
2. 각 UFS LUN의 실제 GPT와 CRC를 읽어 저장합니다.
3. GPT가 알려주는 용량으로 해당 기기의 전체 LUN을 별도 폴더에 읽습니다.
4. 읽기 ACK, 파일 크기, 기본·백업 GPT의 CRC, SHA-256과 독립 파티션 읽기를 교차 검증합니다.
5. 완료 manifest를 기록하고 원본 파일을 보존합니다.

공개 저장소에는 Firehose 및 기기 백업을 배포하지 않습니다. 적합한 로더를 별도로 준비해야 합니다.

## 확인된 디버그 필드

첫 번째 Toss Front 2에서는 `smraw`가 UFS LUN 0에 있었고 물리 섹터 크기는 4096바이트였습니다. 첫 섹터의 다음 필드만 변경했습니다.

| 섹터 내부 위치 | NUL로 끝나는 값 |
| --- | --- |
| `0x300` | `SYSDEBUGMODE=true` |
| `0x400` | `APPDEBUGMODE=true` |

실제 GPT에서 `smraw` 위치를 다시 구하고, 현재 기기의 첫 섹터가 해당 기기 백업과 일치하는지 확인합니다. 비어 있거나 이미 같은 값인 필드만 처리합니다. 전체 파티션을 덮어쓰지 않고 검토한 첫 섹터만 쓴 뒤 같은 위치를 다시 읽어 비교합니다.

첫 번째 기기에서 사용한 섹터 번호 `1701672`는 다른 기기의 쓰기 주소로 하드코딩하지 않습니다. 백업이 다르거나 필드 상태가 예상과 다르면 중단합니다.

2026-10-10 두 번째 기기에서는 이 두 필드의 저장·읽기 대조가 성공해도 정상 부팅 ADB가 열리지 않았습니다. 원본 A/B 부트로더가 읽은 디버그 값을 강제로 `false`로 바꾸는 코드가 확인됐습니다. 이전 서명 ABL A를 승인 후 적용하고 전체 읽기를 검증해도 정상 OS ADB는 열리지 않았고, stock recovery fastbootd 경로로 설치 통신을 확보했습니다. 필드 저장 성공과 디버그 기능 활성화를 구분하고 실제 연결을 확인해야 합니다. [두 번째 기기 진단과 부트로더 적용 기록](second-device.md)을 참고합니다.

## Android 앱 복구

user 0에서 제거한 시스템 앱은 원본 APK가 보존돼 있으면 `cmd package install-existing --user 0 패키지명`으로 복구할 수 있습니다. 사용 중지한 앱은 `pm enable --user 0 패키지명`으로 복구합니다. 개별 구성요소까지 차단했던 경우에는 해당 기기의 이전 구성요소 상태도 복원해야 합니다.

설정 저장과 패키지 상태가 디스크에 반영됐는지 확인하고 Android의 정상 종료 절차로 재부팅합니다. 즉시 `adb reboot`을 실행한 시험에서 직전 변경 일부가 저장되지 않아 다시 적용한 사례가 있었습니다.

원본 UFS 백업을 실제로 다시 쓰는 전체 복구 시험은 하지 않았습니다.

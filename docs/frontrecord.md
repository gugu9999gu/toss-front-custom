# FrontRecord · 레코드 플레이어

첫 번째 Toss Front 2의 YouTube 재생을 턴테이블 화면으로 표시하는 Java 앱입니다. 패키지는 `dev.tossfront.record`입니다. `com.google.android.youtube`와 기존 `local.tossfront.youtubeweb`의 Android 미디어 세션을 대상으로 합니다.

## 사용

홈의 **레코드 플레이어**를 실행합니다. 상단 YouTube 버튼은 현재 연결된 재생 앱 또는 마지막으로 선택한 YouTube 앱을 엽니다. 초기 선택은 YouTube 웹입니다. 아래로 스크롤하면 공식 앱/웹 앱 선택 버튼이 있습니다.

YouTube에서 영상을 직접 선택하고 재생한 뒤 레코드 앱으로 돌아옵니다. 실제 제목·제공되는 채널 정보와 썸네일·재생 시간·재생 상태를 표시합니다. 실제 `PLAYING` 상태에만 레코드가 회전하고, 일시정지·버퍼링·종료 때 멈춥니다. Android의 애니메이션 끄기 설정을 따릅니다. 제공되는 재생 기능만 버튼을 활성화하며, 탐색할 수 없는 영상에서는 위치 조절을 비활성화합니다.

**YouTube 웹에서는 앱 상단의 ‘YouTube 위에 레코드 띄우기’를 사용합니다.** 웹 앱은 다른 앱이 앞에 나오면 재생을 멈추는 동작을 실물에서 확인했습니다. 레코드 창을 띄운 다음 가운데 재생 버튼을 누르면 원래 위치에서 재생이 이어집니다. 레코드가 YouTube 화면 위에 표시되고 원래 웹 앱은 앞에 유지됩니다.

상단 **닫기**로 원래 YouTube 화면을 보며, 상단 YouTube 버튼도 레코드를 닫고 재생 앱으로 돌아갑니다. 표시 중인 알림에서도 닫을 수 있습니다. 아래로 스크롤하면 **오디오 출력 변경**으로 FrontAudio를 엽니다.

재생 정보가 없으면 ‘YouTube 재생을 기다리는 중’으로 표시합니다. 화면에 임의 곡 정보를 넣거나, 미디어 세션이 없는 상태에서 재생 버튼을 작동시키지 않습니다. 공식 YouTube의 기존 재생 오류는 이 앱에서 해결하지 않았습니다. 플레이어가 영상을 재생하지 못하면 레코드 앱도 실제 재생을 표시할 수 없습니다.

## 재생 정보 연결

[MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager)의 활성 세션 조회와 [MediaController](https://developer.android.com/reference/android/media/session/MediaController)의 재생 제어를 사용합니다. 이 API를 이용하기 위한 알림 접근 권한과, 레코드 창의 다른 앱 위 표시 권한을 설치 도구에서 이 앱에만 허용합니다. 앱에서는 일반 알림 내용을 처리하지 않고 YouTube 두 패키지의 미디어 세션만 선택합니다.

Record 앱은 네트워크 권한이 없고 재생 메타데이터를 파일로 저장하지 않습니다. 앱 사용에는 root나 PC 제어 프로그램이 필요하지 않습니다. 설치 이후 재부팅 시험은 진행하지 않았으며, 레코드 창을 부팅 때 자동으로 띄우지는 않습니다.

기존 YouTube 웹 앱은 2.0으로 업데이트했습니다. 공식 모바일 사이트의 현재 HTML 영상 상태와 제목을 읽어 Android 미디어 세션으로 전달하고 재생/일시정지/위치 변경 요청을 해당 영상에 전달합니다. 공개 영상 ID를 검증한 뒤 `i.ytimg.com`의 고정된 썸네일 경로만 가져옵니다. 음원·영상 파일을 추출하거나 내려받지 않습니다. 웹 페이지 구성 변경에 따라 메타데이터 연결이 달라질 수 있습니다.

## 빌드와 설치

Android SDK 33, build-tools 36.0.0, JDK, Python 3.11 이상을 사용했습니다.

```powershell
python tools/build_android.py --app record
python tools/build_android.py --app youtubeweb
python tools/install_record.py --serial FIRST_DEVICE_SERIAL --update-web
```

기존 웹 앱을 업데이트하려면 **그 앱을 처음 서명한 개인 키**가 필요합니다. 실제 첫 번째 기기에서는 기존 키를 로컬 `build/youtubeweb/`에 보존해 같은 서명으로 업데이트했습니다. 공개 저장소에는 서명키가 없습니다. 다른 키로 만든 APK는 기존 앱의 업데이트에 실패하며, 설치 도구는 기존 앱이나 데이터를 삭제하지 않습니다.

레코드 앱만 설치하는 경우 `--update-web`을 제외합니다. 설치 도구는 지정한 일련번호의 Toss Front 2/Android 13/root ADB를 확인합니다. 비어 있는 홈 셀에 앱 바로가기도 추가합니다.

오프라인 미디어 정보 처리 검증은 다음 명령으로 실행합니다.

```powershell
node tests/record_dom.cjs
```

## 실물 검증 · 2026-10-09

첫 번째 Toss Front 2/Android 13에 두 앱을 설치하고 미디어 리스너 연결·다른 앱 위 표시 권한·홈 바로가기를 확인했습니다. 사용자가 YouTube 웹에서 직접 선택해 재생한 영상으로 다음 항목을 확인했습니다.

- 실제 제목·썸네일·재생 시간·전체 길이 표시.
- 레코드 화면의 일시정지로 미디어 세션이 `PAUSED`로 바뀌고 재생 위치와 레코드 중앙 이미지가 정지.
- 레코드 화면의 재생으로 `PLAYING`으로 바뀌고 재생 위치와 회전 이미지가 다시 변화.
- 위치 조절로 영상 중간으로 이동한 뒤 시험 전 재생 위치로 복원.
- 앱 상단 버튼으로 레코드 창을 띄우고, 닫기로 창이 종료되어 원래 웹 앱으로 복귀. 창을 닫은 뒤에도 재생 유지.
- 최종 설치본에서 웹 재생과 리스너 연결 유지. 두 앱의 새 충돌 로그 없음.

빌드·APK 서명 검증, 메타데이터 처리의 오프라인 14개 검증, 공용 빌드 도구의 기존 FrontDeck/FrontAudio 빌드도 통과했습니다. 공개 [검증 결과](frontrecord-verification.json)에는 영상 제목·ID·썸네일·기기 식별 정보를 포함하지 않습니다. 실물 화면과 원시 로그는 로컬에만 보존합니다.

공식 앱의 실제 재생 연동, 설치 후 기기 재부팅, 장시간 연속 재생 시험은 이번 검증에 포함하지 않았습니다. 웹 페이지가 변경되면 재생 정보 연결 보완이 필요할 수 있습니다.

# Toss Front 2 레코드 플레이어 확장 설계안

> 작성: Claude Opus 5.5 · 대상: Android 13 / 800×1280px(약 400×640dp) / 네이티브 Java

## 0. 우선순위와 근거

| 순위 | 항목 | 근거 |
|---|---|---|
| P0 | 공식 YouTube 앱 연결 제거, 재생 중인 영상 보존 | 사용자의 재생을 끊는 회귀가 가장 치명적입니다 |

| P0 | 오버레이 표시와 웹 앱 immersive 연동 | 오버레이 창 혼자서는 시스템바를 숨길 수 없습니다 |

- **안전 여백:** 상하 고정 16dp, 좌우 24dp. 순간 시스템바가 나타나도 레이아웃을 다시 배치하지 않습니다. 레이아웃이 튀는 것을 막기 위해서입니다. 다만 내용은 반투명 바 아래에도 읽히는 위치에 둡니다.
- **세로 높이가 600dp 미만일 때:** 시각화를 높이의 45%로 줄이고 최소 220dp를 지킵니다. 채널 이름은 숨깁니다.
- **가로(640×400dp):** 왼쪽에 시각화 정사각(높이 − 32dp)을 두고, 오른쪽 열(최소 280dp)에 제목, 스크러버, 버튼을 세로로 쌓습니다.
- **제어 버튼:** MediaSession이 제공하는 액션만 그립니다. 이전/다음이 없으면 재생 버튼만 가운데에 둡니다.
- **재생할 미디어가 없을 때:** 시각화 자리에 정지된 레코드와 "재생 중인 곡이 없어요"를 표시합니다.

## 2. 설정 바텀시트

- **열기:** [⋯] 탭 또는 시각화 영역 길게 누르기(500ms)
- **열지 않는 방법:** 하단 가장자리 스와이프. 시스템바 복귀 제스처와 충돌합니다.
- **크기:** 높이 400dp(화면의 약 62%), 상단 모서리 반경 28dp, 핸들 32×4dp
- **닫기:** 아래로 끌기, 바깥 탭, [닫기] 버튼

| 섹션 | 내용 |
|---|---|
| 화면 | 모드 타일 4개(가로 1열, 각 80×88dp, 아이콘과 이름) |
| 테마 | 원형 스와치 4개(지름 40dp, 터치 48dp) |
| 포인트 색 | 원형 5개 |
| 반응 세기 | 낮게 / 보통 / 크게 (세그먼트, 높이 48dp) |
| 움직임 | 시스템 설정 따르기 / 줄이기 |
| 하단 | [웹 화면 보기] [기본값으로] |

- **즉시 적용, 자동 저장:** 별도의 "저장" 버튼을 두지 않습니다. 변경할 때마다 SharedPreferences에 `apply()`로 기록하고, 스키마 버전 키(`prefs_v`)를 둡니다.
- **기본값 복원:** [기본값으로]를 누르면 스낵바 "기본값으로 바꿨어요 · 되돌리기"를 4초 동안 표시합니다.
- **포커스 처리:** 오버레이가 NOT_FOCUSABLE이라 뒤로 가기 키를 받지 못합니다. 그래서 모든 닫기 동작은 터치로 처리합니다. 포커스를 켜는 방식은 웹 재생이 유지된다는 실물 검증이 끝나기 전까지 쓰지 않습니다.

## 7. 모션: 모든 애니메이션은 인터럽트 가능

**원칙**

- 단일 Choreographer 프레임 콜백이 모든 값을 갱신합니다.
- 각 값은 `현재값 + 속도 + 목표값` 상태를 가집니다.
- 새 목표가 들어오면 **현재값과 현재 속도에서 이어서** 보간합니다. 처음부터 다시 시작하거나 끝값으로 점프하지 않습니다.

**개별 모션**

| 대상 | 동작 |
|---|---|
| 레코드 회전 | 목표 각속도 0 ↔ 33⅓rpm 사이를 260ms 가감속. 재생 → 정지 → 재생을 연타해도 속도가 연속적입니다. 레이어 캐시 비트맵에 vsync 회전 transform만 적용합니다 |
| 바늘 | 240ms, 표준 이징, 현재 각도에서 재목표 |
| 재생 아이콘 | 160ms 크로스페이드와 스케일 0.92 → 1 |
| 모드 전환 | 이전 모드의 마지막 프레임을 스냅샷 비트맵으로 떠서 240ms 페이드아웃하고, 새 모드는 바로 라이브로 그립니다. 동시에 두 렌더러를 돌리지 않습니다 |
| 테마 전환 | 모든 색 토큰을 240ms ARGB 보간 |
| 바텀시트 | 열기 280ms 감속. 드래그는 손가락을 1:1로 따라갑니다. 손을 뗄 때 속도가 1000dp/s 이상이거나 절반 아래로 내려가 있으면 닫습니다 |
| 컨트롤 자동 숨김 | 재생 중 4초 동안 입력이 없으면 [⋯]만 200ms 페이드 |

제목, 버튼, 스크러버는 항상 보입니다. 미니멀함보다 조작 가능성을 우선합니다.

**움직임 줄이기**

- 시스템 `ANIMATOR_DURATION_SCALE == 0`이거나 앱 설정이 "줄이기"이면 적용합니다.
- 레코드 회전, 링 회전, 전환 애니메이션을 끄고 즉시 상태를 바꿉니다.
- 오디오 시각화는 실제 데이터 표시이므로 유지하되, 평활화를 늘려(하강 400ms) 깜박임을 줄입니다.

## 8. Immersive 오버레이 처리

**구조적 제약**

- TYPE_APPLICATION_OVERLAY 창은 시스템바보다 아래 레이어에 있습니다.
- NOT_FOCUSABLE이라서 자기 창의 InsetsController로는 바를 숨길 수 없습니다.
- 따라서 **바를 숨기는 주체는 포커스를 가진 웹 앱 Activity**입니다.

**연동 흐름** (웹 앱 래퍼를 수정할 수 있다는 전제)

1. 두 앱을 같은 서명 키로 서명하고 `signature` 수준의 커스텀 권한을 정의합니다.
2. 레코드 서비스는 오버레이를 표시하거나 숨길 때 명시적 브로드캐스트(`OVERLAY_SHOWN` / `OVERLAY_HIDDEN`)를 웹 앱 패키지로 보냅니다.
3. 웹 앱은 SHOWN을 받으면 `hide(systemBars())`와 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`를 적용합니다. HIDDEN을 받으면 `show()`합니다.
4. 시스템이 바를 다시 보여줄 수 있으므로, 웹 앱은 `onResume`과 `onWindowFocusChanged(true)`에서 마지막 상태를 재적용합니다.
5. 오버레이 창 설정: `fitInsetsTypes(0)`, `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`, 전체 800×1280 크기.

**복귀 제스처**

- 상단이나 하단 가장자리를 스와이프하면 시스템 순간 바가 나타났다가 자동으로 사라집니다.
- 오버레이를 완전히 내리려면 시트의 [웹 화면 보기]를 누릅니다. 오버레이가 숨겨지고 바가 복원됩니다.
- 다시 열 때는 기존 홈 바로가기를 사용합니다.

**대체 경로:** 웹 앱이 수정 불가능한 브라우저 PWA라면 바 숨김을 보장할 수 없습니다. 이 경우 "시스템바 유지"를 문서화하고, 우회 해킹은 하지 않습니다.

## 9. YouTube 앱 제거와 기존 영상 보존

**제거 대상**

- `com.google.android.youtube` 관련 `<queries>`, 인텐트, 폴백 코드, 설정 항목을 모두 삭제합니다.
- 공식 YouTube 앱을 가리키는 딥링크 URL 생성도 제거합니다.

**[웹 화면 보기] 동작**

- 데이터 URL 없이 웹 앱 런치 인텐트에 `FLAG_ACTIVITY_REORDER_TO_FRONT`를 붙여 **기존 태스크만 앞으로** 가져옵니다.
- 새 URL 로드, 자동 재생, 위치 이동은 하지 않습니다.

**업데이트 후 첫 실행**

- 오버레이 표시, 설정 마이그레이션(v1 → v2), 서비스 재시작 중 어느 것도 MediaSession에 play/seek 명령을 보내지 않습니다.
- 기존 사용자의 모드는 "레코드"로 유지하고 테마는 "크림"으로 매핑합니다. 새 기능은 시트에서 사용자가 직접 고릅니다.

## 10. 오디오 분석 상태 기계

```
권한없음 ─허용→ 준비중 ─생성 성공→ 수신중 ⇄ 신호없음
              └ 생성 실패/ERROR_NO_INIT → 미지원(세션 동안 재시도 안 함, 다음 실행 시 1회 재시도)
```

**Visualizer 설정과 수명**

- `Visualizer(0)`을 쓰고, 캡처 크기는 512입니다.
- 캡처 주기는 `getMaxCaptureRate()`를 따릅니다. 보통 20Hz이며, 화면은 vsync로 보간합니다.
- 필요 권한은 `RECORD_AUDIO`와 `MODIFY_AUDIO_SETTINGS`입니다. 네트워크 권한은 매니페스트에 넣지 않습니다.

**신호없음 판정**

- MediaSession이 PLAYING인데 1.5초 동안 waveform이 전부 128이고 FFT가 전부 0이면 신호없음으로 봅니다.
- 원인은 볼륨 0, 기기 제한, 세션 0 차단일 수 있습니다.

**해제 시점**

- 레코드 모드, 오버레이 숨김, 화면 꺼짐, 일시정지 후 10초 경과 시 Visualizer를 `release()`하고 프레임 콜백도 멈춥니다.
- 다시 재생하면 재생성합니다.

**스레드 처리**

- 캡처 콜백에서 미리 할당한 float 배열 두 개를 교대로 써서 UI 스레드와 공유합니다.

## 11. 성능 기준

**그리기 규칙**

- `onDraw`에서 객체를 할당하지 않습니다. Path, Paint, float[]는 재사용합니다.
- 링 모드는 `drawLines` 배열 하나로 그립니다(5 × 96 세그먼트).
- 그림자 레이어와 BlurMaskFilter는 금지합니다.

**목표 수치**

| 항목 | 기준 |
|---|---|
| 프레임 | 60fps |
| 모드별 UI 스레드 작업 | 6ms 이하 |
| janky 프레임 | 5% 미만 (`dumpsys gfxinfo`, 60초 측정) |
| 링 모드 | 기준 미달 시 30fps 캡과 이력 3프레임으로 자동 강등 |
| PSS 메모리 | 60MB 이하 |
| 정지 상태 CPU | 1% 미만 |

## 12. 실물 테스트 체크리스트

1. **Visualizer 지원 매트릭스:** 1kHz 테스트 톤 영상을 재생해 FFT 피크가 해당 빈에 오는지 확인합니다. 정지나 음소거 후 0.5초 안에 바닥선과 상태 칩으로 바뀌는지 확인합니다. 볼륨 단계별 진폭 변화도 기록합니다.
2. **마이크 사용 표시기:** 개인정보 마이크 표시기가 켜지는지 확인하고, 결과를 권한 안내 문구에 반영합니다.
3. **재생 연속성:** 오버레이를 50회 표시하고 숨기는 동안, 그리고 시트를 열고 닫는 동안 웹 재생이 끊기지 않는지 확인합니다.
4. **영상 보존:** 업데이트 설치 후에도 재생 중이던 곡의 제목과 위치가 그대로인지 확인합니다.
5. **시스템바 연동:** 바 숨김, 순간 복귀, 재적용이 동작하는지 확인합니다. 화면 회전, 화면 끄고 켜기, 웹 앱 프로세스 재시작 후에도 확인합니다.
6. **오디오 상태 분기:** 권한 거부, 미지원, 신호없음 각 상태에서 가짜 움직임이 없는지 영상으로 녹화해 검토합니다.
7. **설정 저장:** 테마, 포인트, 모드, 움직임 설정이 강제 종료와 재부팅 후에도 유지되는지 확인합니다.
8. **매니페스트 정리:** `aapt dump permissions` 결과에 INTERNET 권한이 없는지, 빌드 산출물에 YouTube 패키지 문자열이 없는지 확인합니다.
9. **움직임 줄이기:** 시스템 애니메이션 0배 설정에서 회전과 전환이 멈추는지 확인합니다.
10. **모션 인터럽트:** 재생 버튼을 100ms 간격으로 연타했을 때 회전 속도와 바늘에 점프가 없는지 확인합니다.
